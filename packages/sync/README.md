# Pi Sync

为 Pi 1.4.x 保存和还原可移植的用户环境。保存以本机为准，还原以远端为准；旧快照保留在 Git 历史，还原前的本机内容保留在备份中。

当前是私有开发包。实现使用 Pi、Node.js 标准库和 Git，没有第三方运行时依赖。

## 开始使用

在本仓库根目录临时加载：

```powershell
pi -e ./packages/sync
```

在 Pi 中连接自己的仓库并保存：

```text
/sync setup git@github.com:your-account/pi-profile.git
/sync include pi-fff.json
/sync save
```

`include` 是可选的，用来纳入额外资源。另一台机器先准备 Pi 和此扩展，再执行：

```text
/sync setup git@github.com:your-account/pi-profile.git
/sync restore
```

还原成功后自行设置所需鉴权并重启 Pi。当前会话不会自动退出或热切换。建议使用专门的仓库或分支；首次连接只验证读取，成功推送后才证明有写权限。

空仓库可直接首次保存。旧的整目录 Git 备份需要在源机器重新执行保存，不会直接当作 Pi Sync 快照解包。Pi Sync 不清理仓库已有文件和历史。

## 命令

| 命令 | 行为 |
|---|---|
| `/sync`、`/sync help` | 显示帮助 |
| `/sync setup <仓库地址> [分支]` | 连接来源；默认使用远端 HEAD 分支，空仓库默认 main |
| `/sync save` | 收集当前环境、过滤已知字段、提交并推送新快照 |
| `/sync restore` | 准备依赖、备份、强制还原受管状态 |
| `/sync status` | 查看来源、远端 commit、待确认保存、最近备份和资源范围 |
| `/sync include <相对路径>` | 额外纳入 Agent Directory 内资源 |
| `/sync exclude <相对路径>` | 取消对应显式资源根；父根覆盖的子路径需先调整父根 |
| `/sync cancel` | 请求取消当前操作，等待停止与必要回退 |
| `/sync recover` | 从中断日志回退未完成的还原；不需要 Git，可在 Git 不可用时使用 |

带空格的参数用单引号或双引号包裹；Windows 参数中的反斜杠按字面处理。请在模型空闲、没有排队消息时操作。配置中明确声明的本地扩展和资源引用会配套保存其 agent 内源码，取消显式根不会移除这些声明。

## 保存范围

尊重 `PI_CODING_AGENT_DIR`，默认只管理 `~/.pi/agent`。项目配置与其他目录不自动打包；外部引用会提示未覆盖。

| 内容 | 规则 |
|---|---|
| 供应商与模型 | 保存接口、地址、兼容参数、模型定义与覆盖，过滤已知鉴权 |
| 通用设置 | 保存默认/启用模型、思考、压缩、工具选择、主题和已支持的交互/显示偏好 |
| 本机设置 | Shell、编辑器、代理、包管理命令、会话位置、信任状态、遥测及机器状态等本机保留；未知设置提示未纳入 |
| 终端设置 | 同步图片显示、宽度、清屏与进度显示偏好；终端协议和颜色/超链接能力在本机保留 |
| npm/Git 扩展 | 固定实际安装的直接版本或 commit，保留启用筛选，目标机重新安装 |
| 本地资源 | 默认包括 extensions、agents、skills、prompts、themes 及全局指令；显式 include 可增加配套资源或自定义配置 |
| 本地依赖 | 保存源码、依赖声明与已有锁定信息，目标机准备依赖，不复制源机器依赖树 |
| pi-fff 配置 | 显式纳入后保存配置，数据库路径仍在本机保留 |
| 排除项 | 独立凭据、环境文件、依赖树、平台二进制、Git 元数据、会话、历史、缓存和 Pi Sync 自身工作内容 |

资源使用相对位置、Base64 内容和 SHA-256 校验存入仓库的 `profile.json`。Base64 是编码，不是加密。JSON 配置与资源要求有效 UTF-8；其他文件按原始字节保存，保留可执行标记。

单文件上限 8 MB，用户资源合计上限 40 MB、10000 个文件。跨平台非法文件名、大小写冲突、符号链接和 junction 会明确拒绝；不会自动跟随链接到其他目录。

未安装或无法确认实际版本的包会使保存失败；不会自动换成最新版本。Git 扩展中未提交的源码修改也会阻止保存。未跟踪的依赖目录及包管理器锁文件按安装产物忽略；固定直接版本/commit 不保证全部传递依赖和外部程序一致。

## 鉴权边界

- 不读取或改写独立的 `auth.json`、`mcp-auth.json`，不导出 `.env`、`.npmrc` 等已知凭据文件。
- 纳入的 JSON 按明确字段名过滤 API Key、Token、密码、Client Secret、私钥和常见认证 Header；纯 `$NAME` / `${NAME}` 引用可保留，字面值与取 Key 命令由目标机器自行配置。
- MCP 等配置中的环境变量值只保留纯变量引用，本机已有的环境值与同身份定义的鉴权字段保留。
- 不扫描源码、Markdown、命令参数、脚本或未知位置中的秘密。未知文本可能随选定资源上传。
- 供应商地址变化直接应用，可能继续使用本机已有 Key。被移除的定义及其附带本机值可从还原备份找回。

只连接可信的仓库和包来源。恢复扩展依赖可能运行安装脚本；脚本在受管范围外造成的副作用不承诺回滚。

## 依赖与镜像

- Pi 1.4.x 稳定版和 Git 2.28+。
- 恢复 npm/pnpm 依赖时，需要可调用的 Node.js 22.19+ 和相应包管理器。Bun 路径不额外要求系统 Node。
- Windows 的 PowerShell shim 需要 PowerShell 7。裸 `.cmd`/`.bat` 无同名 `.ps1` 时会拒绝执行，避免参数被当成命令；可将本机 `npmCommand` 配为原生程序或 `node` 加实际 CLI 脚本。
- 包安装复用目标机器的 `npmCommand` 与 registry/代理配置。需要国内源时可在启动 Pi 的环境设置 `NPM_CONFIG_REGISTRY=https://registry.npmmirror.com`，不会把此机器配置同步到别处。
- 本项目开发依赖下载安装使用国内镜像并优先复用缓存；测试包来自本地 registry 与 Git fixture，不需要真实生产仓库或 Key。

## 备份、失败与恢复

本机工作内容位于 `<agent-dir>/sync`，始终排除在快照之外。`backups/<id>/original` 保存旧受管内容，`journal.json` 描述本次替换；备份可能含原始本机值，仅保存在本机。

扩展与依赖先在隔离阶段准备。备份失败不开始覆盖；受管应用失败尝试回退。若回退也失败，提示受影响项和实际备份位置，执行 `/sync recover` 重试恢复。成功还原后的旧配置也保留在备份中，可按清单手动找回；不会自动清理旧备份。

原生 npm/Git 安装树会在准备成功后切换，旧树留在本机备份；多次还原需预留对应磁盘空间。还原不会清理其他非受管内容。

错误会说明：

1. 操作与失败阶段。
2. 已知原因、退出码和无法确定的部分。
3. 本机及远端是否已修改。
4. 备份、回退状态及可执行的下一步。

仓库不存在与私有仓库无权限无法区分时，会同时提示两种可能。推送回执丢失时先查询远端；无法确定则标记结果未知，可用 `/sync status` 检查待确认 commit。并发推送最多尝试三次，保留历史，不自动合并配置或强推。

## 验证

```powershell
pnpm --filter @pi-plugins/sync check
pnpm --filter @pi-plugins/sync test
pnpm --filter @pi-plugins/sync smoke
```

检查通过公开命令入口，使用临时 Agent Directory、真实本地 bare Git 仓库、本地 npm registry 与 Git 包，以及真实 Pi SDK/CLI。覆盖配置和资源往返、版本固定、鉴权保留、备份回退、错误诊断、竞争、取消、恢复及 print/JSON/RPC 模式；不请求真实模型。

已验证与未验证的平台、Pi 补丁版本和具体结果见 [Pi Sync 验证记录](../../.scratch/pi-sync/verification.md)。macOS 按用户确认的范围标记为尚未实测；支持范围不等于所有系统和补丁版本都已逐一运行。
