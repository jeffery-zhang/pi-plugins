# Hydrogen 默认系统提示词兼容

Status: resolved

## Problem Statement

某些上游会根据 Pi 的默认系统提示词识别客户端并拦截请求。当前遇到这个问题的是 `muryo/gemini-4-hydrogen-sonar`。此前简单的 API 请求和 Pi 工具冒烟可以成功，但实际 SVG 任务仍然失败。用户确认，使用同一模型和 `high` 思考档位，显式传入一段普通的编码助手提示词后可以正常调用。日常使用需要免去每次传参，同时保留 Pi 原提示词的主要编码意图和项目上下文。

## Solution

提供独立扩展 `@jingoz/pi-hydrogen-prompt`。加载后，只有当前模型是 `muryo/gemini-4-hydrogen-sonar` 且本轮使用 Pi 默认系统提示词时，才换成内置的简短编码提示词。Pi 继续管理工具与项目上下文。用户指定自己的系统提示词时优先采用该提示词；切换到其他模型时，下一轮按 Pi 原有规则运行。

## User Stories

1. 作为使用 Hydrogen 的 Pi 用户，我希望直接启动 Pi 就能使用替代提示词，以便省去每次手动传入 `--system-prompt`。
2. 作为使用 Hydrogen 做开发的用户，我希望能完成此前被拦截的实际任务，以便把该模型用于日常编码。
3. 作为依赖 Pi 工具的用户，我希望模型仍知道何时读取、运行命令和编辑，以便完成需要多次工具调用的任务。
4. 作为项目维护者，我希望 Pi 继续加载工程约定和技能，以便编码助手仍能按项目规则工作。
5. 作为自定义提示词的用户，我希望显式提供的系统提示词优先，以便同一个插件不影响我的项目或单次会话定制。
6. 作为会在 Pi 内切换模型的用户，我希望替换仅作用于目标 provider 和模型，以便其他模型维持原行为。
7. 作为会恢复旧会话的用户，我希望下一轮按当前模型选用正确的提示词，以便继续工作而无需重建会话。
8. 作为使用 Pi 1.5.0 或后续版本的用户，我希望插件依赖公开扩展接口，以便升级后不必因版本号变化重新修改插件。
9. 作为在终端或脚本里运行 Pi 的用户，我希望加载扩展无需交互，以便同一套行为可以在 TUI 和无 UI 运行中使用。
10. 作为维护者，我希望能分别验证提示词传输与真实任务结果，以便准确说明某个 Pi 版本和上游是否已验证。

## Implementation Decisions

- `@jingoz/pi-hydrogen-prompt` 是独立的私有 Pi ESM 包，显式声明扩展入口，遵守仓库的包结构和依赖约定。它和 Pi Purge 各自独立。
- 用公开的 `before_agent_start` 回调读取本轮实际模型，只对 provider 为 `muryo`、模型 ID 为 `gemini-4-hydrogen-sonar` 的组合写入 `systemPromptOptions.customPrompt`。加载即启用，不新增会话开关或常驻资源。
- 沿用 Pi 为 `--system-prompt` 使用的自定义提示词组装路径。已有自定义前缀（如 CLI 或 `SYSTEM.md`）或完整覆盖时不接管；缺少可用的结构化选项时保持宿主行为。其他扩展仍按 Pi 的加载顺序执行。
- 由 Pi 自动组装可用的项目指令、技能、补充提示和工作目录；不改实际工具定义、普通对话历史、模型、API 或思考档位。自定义前缀路径会省略 Pi 默认生成的工具说明、规则和文档索引。用简短英文概括其中的主要意图：先了解相关文件，适时使用工具，控制修改范围，验证结果，简洁回复、给出文件路径，涉及宿主时查阅相关文档。
- 首先用用户已跑通的短提示词建立等价对照，再验收保留上述编码行为的最终文案。随包提供一份固定文案，无需外部提示文件。
- 支持目标为 **Pi 1.5.0 及以上**，依赖公开钩子的契约，不以精确版本或 `1.5.x` 作为启用条件。以 1.5.0 和当前本机 1.5.2 验证实现；未来版本的兼容以接口保持为前提，实际验证版本单独记录。此决定只适用于该包，仓库其他插件的通用基线保持原样。

## Testing Decisions

- 主要测试边界是真实 Pi 临时加载包后发往本地模拟端点的请求。沿用 Pi Purge 的宿主与模拟端点测试先例；断言可观察的请求和任务结果。包级 `check` 和 `test` 均须通过。
- 固定模型、输入、工具、项目夹具和 thinking，比较短提示词经 CLI 与插件两种方式生成的请求。覆盖保留工具定义、AGENTS 规则、自定义提示优先及其他模型不替换；验证换入、换出和恢复旧会话后的请求，以及工具调用后的后续请求。
- 在 Pi 1.5.0 和 1.5.2 上实际触发钩子，至少覆盖无 UI 的临时加载，并确认最终文案可用于交互会话。测试默认使用本地端点，不依赖生产凭据或模型配额。
- 最终效果用真实 Hydrogen 验收。固定 `muryo/gemini-4-hydrogen-sonar`、当前 `openai-completions`、`high` 和相同任务及上下文，对比已成功的短提示 CLI 与插件最终文案。以此前失败的 SVG 任务完成且工具调用后的后续请求正常作为效果判据。单次 HTTP 200 或短回复只能证明连通。

## Out of Scope

- 其他 provider 或模型的自动适配、按错误猜测原因、自动重试或回退。
- 修改 Pi 安装、模型配置、网络协议、请求头、工具权限、凭据或其他扩展。
- 新增插件命令、提示词管理界面、可配置规则、完整请求日志、安装或发布。

## Further Notes

- 上游按默认提示词识别并拦截 Pi 是本功能的背景；替代提示词解决的是当前确认的兼容场景，不能用来判定每次 `429` 的原因，也不保证上游策略变化后长期有效。
- 对照结论区分实际提示词传输、工具链和任务完成情况。记录验证条件和结果即可，不保存凭据、私有提示正文、真实工具参数或结果。
