# 01: 连接仓库并解释环境与访问问题

**What to build:** 用户能在 Pi 中首次连接自己的 Git 仓库，保存必要的本机来源设置，确认仓库能否读取，并从明确提示中处理环境、网络、鉴权或权限问题；不需要给 Pi Sync 托管 Token。

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 作为独立 Pi 扩展临时加载，用户可实际触发首次连接命令；默认只注册和初始化，复用 Pi 命令及目录能力，不提前启动长期资源。
- [x] 限定 Pi 1.4.x 稳定版，范围外给出当前版本和支持范围，保持原环境，不自动更新 Pi 或其他插件基线。
- [x] 接受必要的仓库来源和分支设置，记录在本机非快照状态中，复用现有 Git SSH/HTTPS 鉴权，不保存凭据。
- [x] 真实检查当前进程能否调用 Git，区分命令不可见、不可执行、版本问题与执行失败；连接步骤不误要求尚未使用的 Node 或包管理器。
- [x] 能连接可读取仓库及尚无提交的仓库；明确“可读取”“尚无快照”和“写权限未验证”，不通过空提交或试写远端宣称连接验证。
- [x] 区分来源/分支问题、DNS、超时、代理、TLS、SSH 校验、明确认证失败与读权限问题；服务端无法区分私有仓库不存在和无权限时保留两种可能。
- [x] 提示包含失败阶段、原因、是否改动本机或远端及具体处理方式；过滤已知凭据，不输出完整环境变量。
- [x] 无 UI 时有参数可继续，缺少参数时明确失败，不等待无法呈现的对话框；按模式守卫使用 UI。
- [x] 从公开命令入口，使用临时环境和本地 bare Git 仓库验证成功与空仓库；通过外部 I/O 故障验证缺 Git、超时、认证和权限提示，不 mock 连接流程。
- [x] 提供可运行检查与首次连接最小使用说明；实际 Pi 临时加载触发该命令，记录证据，不安装到用户环境。
