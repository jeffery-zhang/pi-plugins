## 目标

在 Windows、macOS、Linux 上，一键保存和还原用户的 Pi 供应商、模型、扩展与通用配置。P0 各项及整体理解均已由用户确认；用户随后要求生成正式规格与任务文档，尚未实施插件、安装、同步或目录清理。

## 已确认的 P0 决策

| 编号 | 决策 | 已确认要求 |
|---|---|---|
| P0-01 | 内容范围 | 原生可移植配置、扩展声明及选定的 agent 内本地用户资源；扩展自定义文件显式纳入 |
| P0-02 | 还原语义 | 在受管范围内与快照一致；还原前备份，主动还原即强制应用覆盖和删除，不逐项确认；本机鉴权及明确保留的本机设置不替换 |
| P0-03 | 扩展版本 | 固定保存时已安装的直接 npm 版本或 Git commit，保留资源启用筛选；目标机重新安装 |
| P0-04 | Pi 版本 | 首版支持 Pi 1.4.x 稳定版，记录创建与目标版本；不自动升级 Pi，范围外阻止还原 |
| P0-05 | 敏感信息 | 只过滤已知敏感字段和凭据文件；其他位置不扫描、不审核，不增加通用秘密检测流程 |
| P0-06 | 供应商变化 | 地址或接口协议变化也直接应用，不另行确认；原配置留备份，本机鉴权仍保留 |
| P0-07 | 失败处理 | 受管配置、文件或扩展准备失败则整次失败，回退受管文件和声明；下载缓存可保留，安装脚本的外部副作用不承诺事务回滚；缺少 Key 单列待鉴权，不算还原失败 |
| P0-08 | 生效时机 | 完成磁盘还原后报告“已还原，待重启”，由用户重启，不自动退出当前会话 |
| P0-09 | 保存方向 | 保存以本机为准，提交为远端最新快照，旧版本保留在 Git 历史；还原以远端为准，旧配置保留本地备份；不自动合并配置、不改写 Git 历史 |

## 范围与流程

- 存储沿用 Git/GitHub。命令名、仓库布局和插件包名仍是实现草案。
- Agent Directory 默认为 `~/.pi/agent`，尊重 `PI_CODING_AGENT_DIR`；`~/.pi` 其他目录、项目和目录外自动发现的资源不纳入，只报告未覆盖的引用。
- 包括供应商与模型定义、默认/启用模型、通用偏好、包声明及启用筛选，选定的本地扩展、角色定义、提示词、Skills、主题和全局指令。
- 不复制安装目录、平台二进制、依赖树、会话、历史或缓存。Pi Sync 自身的工作副本、备份、状态和日志也不进入环境快照。
- 不读取或导出 Provider/MCP 凭据文件的内容。已知鉴权字段的非秘密环境变量引用可保留，字面鉴权值及取 Key 命令不导出；目标机器自行设置鉴权，包括必要的非秘密占位 Key。
- 本地备份可包含还原前原始配置，只保存在本机，不参与远端快照。强制应用仍需验证快照格式、路径范围与写入条件，遇到非法内容应失败。
- 保存：预检 → 收集并过滤 → 验证 → 获取远端最新历史 → 新建快照提交 → 正常推送。若推送期间远端又有更新，获取新历史后以同一份本机快照重新提交，采用有界重试，不配置合并、不强推。
- 还原：预检 → 拉取并验证快照 → 准备扩展与依赖 → 备份 → 替换受管状态 → 报告待鉴权/待重启。失败按 P0-07 回退，不自动加载新扩展到当前会话。

## 错误提示与诊断：完成标准

用户补充明确要求：仓库连接、权限、Git、Node 等情况必须给出清楚提示。这是首版验收要求，不是可选增强。

### 每次错误需要说明

1. 失败的操作和阶段，例如保存/推送、还原/准备扩展、还原/回退。
2. 已确认的原因与仍无法确定的部分；有证据才判断为权限不足、仓库不存在或认证失败。
3. 影响范围：本机受管配置是否修改、远端是否更新、是否仍有待确认的远端结果。
4. 备份位置、回退是否成功，以及可以采取的具体下一步；未生成备份时不能给出虚假备份位置。
5. 对应命令的退出码和必要的已过滤诊断；错误提示和日志不输出凭据值或完整环境变量。

### 至少覆盖的情况

| 类别 | 需要区分与说明 |
|---|---|
| Git 不可用 | 当前 Pi 进程找不到命令（可能未安装或 PATH 未生效）、程序不可执行、版本不满足；说明安装或重新启动终端/Pi 后检查 |
| 运行时/包管理器不可用 | 按实际调用方式检查 Node、npm、pnpm、Bun 或自定义 npmCommand；区分命令缺失、版本不兼容、命令可启动但执行失败；不能把 Node 一律当成独立 Pi/Bun 路径的必需项 |
| Pi 版本不支持 | 显示当前版本和支持范围 1.4.x，保持原环境，不自动升级 Pi |
| 本地目录问题 | Agent Directory 不存在、不是目录、不可读写，临时目录或备份创建失败，磁盘空间不足，文件被占用，已有同步操作正在执行 |
| 仓库配置问题 | 未配置来源、地址格式无效、来源对应的本地路径不可访问、目标分支不存在 |
| 仓库连接问题 | DNS、连接超时、代理、TLS 或 SSH 主机身份校验失败；保留实际原因，不统一写成“网络错误” |
| 鉴权与权限 | 区分已明确的 SSH key/HTTPS 认证失败、缺少读取权限、缺少推送权限、保护分支/服务策略拒绝；私有仓库的“找不到”可能表示无权限，证据不足时同时提示两个可能 |
| Git 提交失败 | 提交身份未配置、仓库锁或本地工作副本异常、提交命令失败；不能仅检查 Git 是否存在 |
| 没有快照 | 仓库可连接但尚无提交、指定版本不存在、没有可识别的环境快照；说明源机器需要先保存 |
| 快照无效 | JSON/必需字段/格式版本错误、快照不完整、校验失败、非法相对路径或试图越出受管根；不执行部分应用 |
| 扩展与依赖失败 | 指明具体包和目标版本，区分版本不存在、包仓库无权限、下载超时、安装脚本失败、系统/架构不支持或所需外部程序不可用 |
| 推送竞争或结果不明 | 正常处理远端在推送前再次变化；有界重试耗尽时说明远端已变化且本次未完成。连接断开时若无法确认服务端是否已接收，先查询验证，无法验证则报告结果未知 |
| 应用或回退失败 | 指明失败文件和阶段；回退成功说明原受管配置已恢复，回退失败列明受影响项和实际备份路径，不能仍报告“原环境未变” |
| 用户取消或超时 | 显示取消阶段及已有改动，停止后续步骤，必要时回退；不继续后台写入或推送 |
| 未识别的错误 | 显示阶段、退出码及经过已知凭据过滤的诊断，保留不确定性，提供可用于定位的原因信息 |

### 提示示例

```text
保存失败：推送远端时被拒绝。
原因：服务端明确提示当前 Git 账号没有推送权限。
影响：本机快照已生成，本次远端更新未成功。
处理：为当前账号授予仓库写权限，或改用有权限的 Git 凭据后重试保存。
```

```text
还原失败：准备扩展 npm:@example/tool@1.2.3 时下载超时。
影响：尚未替换本机受管配置，原环境保持原状。
处理：检查 npm registry 与代理连接后重试还原。
```

以上是确定对应状态时的文案示例，不能对结果未知或已部分写入的操作套用。

## 验收边界

- 配置与资源还原成功不等于已鉴权或已能推理；缺少 Key 属于待鉴权。
- 固定直接扩展版本不保证所有传递依赖、平台工具、硬件或外部程序完全一致。
- 只过滤已知敏感位置，其他文本或未知配置中的秘密可能随资源上传；同 ID 的供应商更换地址后可能继续使用本机 Key。
- 覆盖与删除在受管范围内进行，受管范围之外的本机内容保留；备份失败时不能开始覆盖。
- 明确区分“本地快照已生成”“远端已更新”“磁盘还原完成”“已回退”“待鉴权”“待重启”和“结果未知”。不能只返回笼统的同步成功/失败。
- Pi Sync 的支持范围为 Pi 1.4.x；目前调查证据来自 1.4.0，不等于所有补丁版本和操作系统都已验证。其他插件及仓库的 0.84.3 基线不自动改变。
- 实施时为关键失败路径保留最小可运行检查，包括缺失命令、仓库访问失败、无效快照、扩展准备失败、备份/回退失败以及远端推送竞争；不把仅成功路径的冒烟当作错误处理已完成。
