# Pi Sync：环境快照规格

Status: resolved
Review: 用户已确认并授权实施；七张任务已完成，实际验证范围见 verification.md。

## Problem Statement

用户在多台 Windows、macOS、Linux 机器上使用 Pi，需要重复配置供应商、模型、扩展和偏好。直接把整个 Pi 用户目录提交到 GitHub 会混入安装产物、平台二进制、运行状态，以及可能存在的鉴权信息；只复制包声明又不能重建本地扩展、配套角色和当前实际使用的扩展版本。

用户希望用明确的保存和还原动作重建可移植的 Agent Environment，保留旧状态以便恢复。API Key、Token 和登录鉴权由各机器自行管理。发生连接、权限、依赖或文件操作问题时，用户必须能知道失败在哪里、已经改了什么以及如何处理。

## Solution

提供 Pi Sync Module，通过 Pi 用户命令完成首次连接、Save 和 Restore。

Save 以本机为准，收集 Managed Scope 中的可移植内容、过滤已知敏感位置，生成 Environment Snapshot 并提交为远端最新版本，既有版本保留在 Git 历史中。Restore 以远端为准，在目标机器准备依赖、创建 Restore Backup，然后强制替换受管状态；地址变化、覆盖和删除不逐项确认。目标机器的独立鉴权与明确保留的本机设置继续保留。

首版支持 Pi 1.4.x 稳定版和三种桌面系统。还原失败时回退受管文件和声明，缺少 Key 单列待鉴权；完成磁盘还原后提示用户重启。错误提示贯穿每个阶段。

## User Stories

1. 作为 Pi 用户，我希望首次连接自己的 Git 仓库，以便后续从同一来源保存和还原环境。
2. 作为 Pi 用户，我希望复用机器已有的 Git 鉴权，以便不用把仓库 Token 交给扩展托管。
3. 作为 Pi 用户，我希望看到仓库读取是否成功及尚未验证的写权限，以便连接成功不会被误解为一定能够推送。
4. 作为 Pi 用户，我希望对空仓库完成第一次保存，以便不用手动创建一个占位快照。
5. 作为 Pi 用户，我希望保存供应商的地址、接口类型和兼容参数，以便另一台机器重建相同定义。
6. 作为 Pi 用户，我希望保存自定义模型和模型覆盖，以便保留上下文长度、推理能力和其他元数据设置。
7. 作为 Pi 用户，我希望保存默认与启用模型，以便新会话使用相同的模型选择偏好。
8. 作为 Pi 用户，我希望保存可移植的通用设置，以便主题、思考和压缩等偏好可以恢复。
9. 作为 Pi 用户，我希望只保存用户层设置，以便当前项目的临时或专属设置不会变成全局默认值。
10. 作为 Pi 用户，我希望本机 Shell、代理、编辑器和目录等设置被保留，以便另一台机器的路径不会破坏当前机器。
11. 作为 Pi 用户，我希望固定保存时实际安装的 npm 扩展直接版本，以便还原时不会意外安装最新版本。
12. 作为 Pi 用户，我希望固定 Git 扩展的实际 commit，以便还原时不会因分支或标签移动得到另一份代码。
13. 作为 Pi 用户，我希望保留扩展资源启用筛选，以便只加载我选定的扩展、Skills、提示词和主题。
14. 作为 Pi 用户，我希望重新安装扩展依赖，以便不用复制当前机器的依赖树和二进制。
15. 作为 Pi 用户，我希望保存本地扩展源码和必要的依赖声明，以便包清单之外的扩展也能恢复。
16. 作为 Pi 用户，我希望保存本地扩展配套的角色定义，以便还原后的 Subagent 具有相同角色。
17. 作为 Pi 用户，我希望保存选定的提示词、Skills、主题、快捷键和全局指令，以便个人工作方式能够恢复。
18. 作为 Pi 用户，我希望显式纳入扩展自定义资源和可移植设置，以便这些内容不会因为不在原生目录清单中而遗漏。
19. 作为 Pi 用户，我希望目录外的资源引用被报告为未覆盖，以便我知道仅还原 Agent Directory 的能力边界。
20. 作为 Pi 用户，我希望缓存、历史、会话、安装产物和扩展自己的备份不进入快照，以便快照保持可移植且不会递归增长。
21. 作为 Pi 用户，我希望已知敏感字段和凭据文件被过滤，以便常见的 Key 和 Token 不被导出。
22. 作为 Pi 用户，我希望非秘密的环境变量引用可以保留，以便我在目标机配置变量后继续使用原有定义。
23. 作为 Pi 用户，我希望其他资源不经过通用秘密扫描或人工审核流程，以便保存动作保持简单。
24. 作为 Pi 用户，我希望目标机已有的鉴权信息被本机保留，以便还原定义不会替换我的登录和 Key。
25. 作为 Pi 用户，我希望还原前存在可定位的本地备份，以便能够找回旧配置及其附带的本机值。
26. 作为 Pi 用户，我希望受管内容按快照强制还原，以便目标机独有的受管条目不会持续累积。
27. 作为 Pi 用户，我希望供应商地址或协议变化直接应用，以便主动还原无需逐项确认。
28. 作为 Pi 用户，我希望受管范围外的内容保持原样，以便保存与还原不会改动整个用户目录或项目。
29. 作为 Pi 用户，我希望备份失败时立即停止还原，以便旧状态不会在没有恢复副本时被覆盖。
30. 作为 Pi 用户，我希望还原遇到受管文件或扩展准备失败时回退，以便不留下被错误报告为成功的半套环境。
31. 作为 Pi 用户，我希望回退失败时看到受影响项和备份位置，以便可以手动恢复。
32. 作为 Pi 用户，我希望缺少供应商鉴权被列为待处理，以便能够区分配置恢复和实际推理可用。
33. 作为 Pi 用户，我希望还原完成后自行重启 Pi，以便不会在当前会话中途被退出或热切换。
34. 作为 Pi 用户，我希望机器 B 保存时以机器 B 为准，同时保留机器 A 的旧版本，以便覆盖方向清晰且旧快照仍可追溯。
35. 作为 Pi 用户，我希望推送期间的远端变化得到有界处理，以便不用手动解决配置合并或改写提交历史。
36. 作为 Pi 用户，我希望连接中断时准确显示远端结果是否已知，以便不会把可能已成功的上传误判为确定失败。
37. 作为 Pi 用户，我希望取消后停止后续操作并报告实际状态，以便不会在后台继续覆盖或推送。
38. 作为 Pi 用户，我希望同时发起的同步操作得到明确处理，以便它们不会相互覆盖工作副本或备份。
39. 作为 Pi 用户，我希望 Git 不可用时区分命令找不到、不可执行和版本问题，以便知道应该安装、修复 PATH 还是更新工具。
40. 作为 Pi 用户，我希望按实际执行路径检查 Node 和包管理器，以便可用的独立 Pi 或 Bun 环境不会被错误阻止。
41. 作为 Pi 用户，我希望连接失败时看到 DNS、超时、代理、TLS 或 SSH 的实际原因，以便能针对性修复网络。
42. 作为 Pi 用户，我希望鉴权、读取、推送权限和保护分支问题得到区分，以便不会用错误方式反复重试。
43. 作为 Pi 用户，我希望私有仓库的不存在与无权限无法区分时被如实说明，以便提示不会猜测事实。
44. 作为 Pi 用户，我希望空仓库、缺少快照、无效格式和版本不支持得到明确说明，以便原环境保持可恢复。
45. 作为 Pi 用户，我希望扩展安装失败时显示具体包、目标版本和失败阶段，以便能够处理下载、访问和平台依赖问题。
46. 作为 Pi 用户，我希望错误说明本机、远端和备份的实际状态及下一步，以便可以可靠重试或恢复。
47. 作为 Pi 用户，我希望诊断和日志过滤已知凭据，以便排查问题不会直接输出 Key 或整个环境变量集合。
48. 作为 Pi 用户，我希望无对话框的运行环境也不会卡住，以便已有参数可以执行，缺少参数时能明确失败。
49. 作为 Pi 用户，我希望 Pi 版本不支持时保持原环境并显示支持范围，以便扩展不会替我自动升级 Pi。
50. 作为 Pi 用户，我希望跨系统验证结果有真实记录，以便知道哪些系统与 Pi 补丁版本已经验证。

## Implementation Decisions

### Module 与接口

- 新增独立的 Pi Sync Module，复用 Pi 的命令注册、目录解析、包管理能力，以及 Node 标准库和 Git。没有现有同步实现需要预先重构。
- 用户接口围绕首次连接、Save、Restore 三个动作；具体命令名称属于实施细节。命令只接受必要配置，复用本机 Git 鉴权，不注册模型可调用的凭据或同步工具。
- 同步逻辑集中在该 Module，测试与用户通过同一组命令接口进入；仅在实际 I/O 边缘需要时提供最小故障注入，不建设通用存储、秘密扫描或错误框架。
- Factory 负责注册与一次性初始化；工作按用户动作启动，取消及会话结束时释放资源。对话框与终端能力遵守 Pi 模式守卫。

### 范围、版本与快照合同

- Agent Directory 是唯一受管根，尊重 Pi 的用户目录覆盖机制。项目、用户目录外自动发现内容与外部路径不自动跟随，只报告未覆盖引用。
- 原生可移植配置与选定的本地用户资源进入 Managed Scope；扩展自定义文件显式纳入。自身工作副本、状态、备份和日志始终排除。
- 环境快照记录格式版本、创建时间、创建时的 Pi 版本、所选内容类别、经过过滤的配置、扩展来源及确定的直接版本或 commit、资源启用筛选、受管资源的相对位置和内容。
- 模型配置保留供应商和模型稳定身份、接口定义与元数据覆盖；用户设置从用户层采集，受管字段按快照替换，本机字段按保留规则维持。
- 资源筛选中省略、空集合、包含和排除的原生含义需要保留，不能简化成来源字符串而丢失启用状态。
- 仅声明支持 Pi 1.4.x 稳定版，保存创建与目标版本，范围外阻止还原。记录已验证的版本和系统，不将研究过 1.4.0 等同于全范围已验证；不改变其他插件基线。
- 校验快照格式、必需信息、内容完整性和受管路径。绝对路径、父级逃逸、越界链接及其他导致读写离开受管根的内容必须拒绝，且不能产生部分应用。

### 已知敏感字段与本机鉴权

- 只维护明确的凭据文件及结构化字段规则，覆盖已知的 Provider 和 MCP 鉴权位置；不读取或导出独立凭据文件内容，不按任意文本或可疑字符串启发式扫描资源。
- 已知鉴权字段中的纯环境变量引用可以保留，字面鉴权值和取 Key 命令不导出；目标机自行补充鉴权及必要的非秘密占位值。
- 任意源码、Markdown 和未知配置不增加审核或秘密扫描流程。快照不承诺不存在未知位置的秘密。
- 已有本机独立鉴权不替换；仍存在的同身份定义中的本机鉴权字段按保留规则处理。删除定义前，其旧配置及附带值由本地 Restore Backup 保留，不上传远端。
- 同身份供应商地址或协议改变也按快照强制应用，不额外询问；本机凭据可能随新定义继续使用，此行为已经用户确认。

### Save 与 Git 历史

- 首次连接记录必要的本机仓库配置，识别可读取状态；未通过真实推送验证前，不宣称已有写权限。空仓库允许首次 Save，Restore 则报告尚无快照。
- Save 收集并验证当前本机状态，再基于远端最新历史提交新的 Environment Snapshot，保留此前提交。包无法解析为实际安装版本时明确失败，不静默改用最新版本。
- 远端在推送期间变化时，重新获取历史，以同一份本机快照提交下一版本并有界重试；不自动合并不同机器的配置，不改写远端历史。
- 推送连接中断后先验证远端是否接受本次结果；无法验证时显示结果未知。区分本地快照已生成与远端已更新。

### Restore、备份与回退

- Restore 先验证输入并准备扩展和依赖，再创建 Restore Backup，成功后替换受管状态。备份失败不开始覆盖。
- 覆盖与删除在受管范围内按快照强制进行，保留范围外的本机内容。受管定义不再需要的资源停止生效，旧文件可从备份找回。
- npm 扩展固定保存时已安装的直接版本，Git 扩展固定实际 commit，目标机重新安装。用户修改过的安装产物不能被误当作可从远端重建的源码。
- 本地资源携带必要的源码、配套文本、依赖声明及已有锁定信息，按目标机器安装方式重建；不复制依赖树、平台二进制、缓存或运行历史。
- 准备或应用受管内容失败时整次还原失败，回退受管文件与声明。下载缓存可保留，安装脚本对受管范围外的副作用不承诺事务回滚。
- 回退失败明确报告受影响项与真实备份位置。缺少供应商 Key 是待鉴权状态，不是还原失败。
- 成功写入后报告已还原、待重启，由用户自行重启，不自动退出当前会话，也不将新扩展立即加载到旧运行时。
- 同一工作副本的操作需要互斥；取消、超时和会话结束停止后续子进程与文件操作，按已有改动进行必要回退并报告实际结果。

### 预检与错误提示合同

- 依当前操作验证 Git、实际需要的 Node/包管理器或自定义安装命令、Pi 版本、受管目录和备份写入条件。区分缺少工具、当前 PATH 不可见、不可执行、版本不满足和命令执行失败。
- 每条错误包含操作与阶段、已知原因和不确定性、本机及远端是否修改、备份与回退状态、具体下一步，以及可用的退出码和经过已知规则过滤的诊断。
- 仓库错误覆盖来源/分支配置、DNS、超时、代理、TLS、SSH、认证、读取权限、推送权限、保护分支和提交身份。私有仓库不存在与无权限不能可靠区分时，同时保留两种可能。
- 文件与快照错误覆盖不可读写、空间不足、文件占用、操作冲突、无快照、格式/版本/内容校验错误、非法路径、备份失败和回退失败。
- 扩展错误指明包与目标版本，区分版本不存在、下载或访问失败、安装脚本失败、平台不兼容与外部依赖缺失。
- 结果明确区分本地快照已生成、远端已更新、磁盘还原完成、已回退、待鉴权、待重启、取消和结果未知。不能用无依据的成功或原环境未变提示替代真实状态。
- 日志不输出已知凭据值或完整环境变量；未知错误保留必要诊断和不确定性。没有对话框时仅使用已提供参数，缺参直接给出可操作提示。

## Testing Decisions

### 已确认的唯一产品测试入口

通过 Pi 已注册的首次连接、Save、Restore 命令测试 Pi Sync Module。测试断言命令的可观察行为、文件与快照内容、Git 历史、Restore Backup 及用户提示，不断言私有函数结构、内部调用顺序或模块拆分。

使用临时 Agent Environment、真实本地 bare Git 仓库和最小本地包 fixture。网络、子进程、文件写入等难以稳定重现的失败只在真实 I/O 边缘注入；同步流程本身不替换为 mock。真实 Pi 宿主冒烟沿用同一命令入口，不另造测试专用同步接口。

### 覆盖的外部行为

- 初次连接、可读取但写权限未验证、空仓库首次保存与空仓库还原失败。
- 从源环境 Save、在含额外内容的目标环境 Restore，证明受管内容一致，本机保留值和范围外内容不变。
- 已知凭据位置被过滤、纯环境变量引用保留、任意其他文本不触发通用扫描，独立凭据文件不读取不改写。
- npm 直接版本和 Git commit 固定、资源启用筛选、目标机依赖准备；实际版本无法确认或安装失败时不伪装成功。
- 本地扩展及配套角色、提示词和其他选定资源的保存与还原；安装产物、自身备份、外部路径和越界链接不能被误导出或应用。
- 备份前失败、应用中途失败、备份失败、回退失败、用户取消与超时；检查实际状态及提示是否一致。
- 两台机器先后 Save、推送竞争、有界重试耗尽、推送结果未知；保留历史且不发生配置自动合并或强推。
- Git/运行时/包管理器不可用，Git 身份、仓库鉴权与权限、网络、快照、文件、扩展和平台依赖错误，覆盖明确原因与不能确定原因两类情形。
- 缺少 Key 后状态为待鉴权，磁盘还原成功后状态为待重启；不请求真实模型、不自动退出当前会话。
- 无 UI 参数完整与缺失、不同模式守卫、会话关闭后的进程停止、同一工作副本互斥。
- 按用户后续确认在 Windows、WSL Ubuntu 和当前可用的 Pi 1.4.x 版本做实际命令冒烟；macOS 无可用环境，明确标记尚未实测。未运行的平台或版本不能由模拟值替代实测。

### 仓库先例与完成门槛

- 仓库的 Pi Purge 已通过注册命令的 harness 验证公开行为，并用真实 SDK/CLI 与临时环境验证宿主合同，可以沿用这一测试方式。
- Windows Toast 已有进程失败与模式守卫测试，Image Input 已有用户路径与故障恢复检查；复用 Node 自带测试工具和断言，不新增测试框架。
- 每个垂直任务同时交付对应的成功与关键失败检查；包声明的检查和测试必须运行，最后临时加载扩展实际触发新增命令及相关取消、无 UI、错误路径。
- 验证不使用用户真实 Agent Environment、凭据、生产仓库或真实推理请求。真实远端连接冒烟只能使用专用测试仓库及已获授权的操作。

## Out of Scope

- API Key、Token、OAuth 登录态、系统环境变量值的跨机器托管、加密与解锁。
- 通用秘密扫描、未知配置或任意源码的自动脱敏、资源内容审核流程。
- 项目环境、Agent Directory 外自动发现资源、整机软件、会话和模型调用历史的同步。
- 后台常驻、实时监听、双向自动合并、多 Profile、团队权限、自建服务和网站。
- Pi 自动升级、其他插件兼容基线调整、Git 历史改写、自动配置仓库凭据或权限。
- 自动热切换当前会话、自动退出 Pi，及保证安装脚本外部副作用可回滚。
- 保证全部传递依赖、外部程序、平台二进制、硬件和所有 Pi 补丁版本完全一致。
- npm 发布、提交或推送本项目仓库，以及清理用户目录；当前任务已授权插件实现和隔离环境中的实际 Pi 验证。
