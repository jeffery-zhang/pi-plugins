# 07: 交付跨系统与无 UI 的实际命令流程

**What to build:** 用户在支持的 Windows、macOS、Linux 和不同 Pi 运行模式中，能够使用同样的连接、Save、Restore 流程，正确处理本机工具与路径差异，并依照明确提示完成鉴权、重启和失败恢复。

**Blocked by:** 04: 固定并重建 npm 与 Git 扩展；05: 保存和还原本地用户资源；06: 在竞争、取消和中断后保持状态可解释。

**Review:** approved-and-published (historical draft)

- [ ] 完整流程跨源环境与目标环境运行，包含原生配置、固定包版本及筛选、本地资源、备份、回退、待鉴权和待重启，保持前面各票的覆盖方向与排除规则。
- [ ] 修复实际系统差异造成的路径、命令解析、文件占用、权限和外部程序检查问题；按当前进程与实际安装方式诊断 Git、Node 和包管理器，不假定所有机器都使用同一个 Shell。
- [ ] 在 Windows、macOS、Linux 可用的真实环境和 Pi 1.4.x 代表补丁版本临时加载并实际触发用户命令，记录成功与关键错误路径；没有实际运行的平台或版本明确保留未验证，不以模拟值冒充实测。
- [ ] TUI、RPC 和无 UI 情形使用正确守卫，有完整参数时执行已支持的动作，缺参时给出下一步，不等待不可显示的对话框，不把诊断插入模型对话。
- [ ] 模型或 Provider 缺少鉴权时只报告待鉴权，不发真实推理请求；还原完成后由用户重启，不自动终止或热切换当前会话。
- [ ] 对错误提示矩阵做公开命令验收，至少覆盖命令不可用、网络和访问权限、空仓库、无效快照、扩展准备、备份和回退失败、竞争与未知结果，具体错误处理已在对应票交付而不是留到本票补做。
- [ ] 用户文档说明首次连接、保存与还原、Git 凭据准备、手动鉴权、受管范围、版本固定边界、备份找回和错误排查，并给出真实验证范围。
- [ ] 保持包私有开发状态及显式 Pi 扩展入口，运行声明的 check/test 与实际宿主冒烟；没有用户额外授权不安装到用户环境、不发布包或推送仓库。
- [ ] 验证记录区分已经执行和环境限制导致未执行的项目；若支持范围仍有阻止交付的真实失败，继续修复或明确留为未完成，不能以文档说明替代功能完成。
