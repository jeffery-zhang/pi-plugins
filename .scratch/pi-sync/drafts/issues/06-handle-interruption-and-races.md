# 06: 在竞争、取消和中断后保持状态可解释

**What to build:** 用户在两台机器竞争保存、连接中断、取消或关闭 Pi 时，能够知道快照是否已经发布、文件是否已经替换或回退，并且不会在操作结束后继续发生后台覆盖。

**Blocked by:** 03: 备份并强制还原原生配置。

**Review:** approved-and-published (historical draft)

- [ ] 两台机器依次 Save 始终以最后主动保存的本机快照形成远端新版本，历史保留，不做配置自动合并或改写历史。
- [ ] 推送期间远端再次变化时重新读取最新历史，并以同一份本机快照提交下一版本；有界重试耗尽明确失败，不无限等待，不使用强推掩盖竞争。
- [ ] 推送连接中断后查询远端是否已接受本次结果；无法确认时报告结果未知，不能盲目声称远端未更新或重复发布成功。
- [ ] 取消、超时及会话结束传递到实际子进程和 I/O，停止后续阶段；Restore 已产生受管改动时按回退合同恢复并报告真实结果。
- [ ] 同一工作副本的操作互斥，第二次操作给出可处理提示；进程异常结束后的锁或操作记录不能被误认成永久运行，也不能在不确定状态下直接破坏恢复资料。
- [ ] 重试或恢复能区分本地快照已生成、远端已更新、已备份、已替换、已回退和未知结果；不丢失可恢复状态或误报原环境未变。
- [ ] 已下载的缓存可以保留，原始本地备份不得被重试覆盖掉；已知凭据不出现在命令参数展示或诊断日志中。
- [ ] 在真实本地 Git 历史中从公开命令制造两客户端竞争，验证完整历史和最终快照；通过 I/O 边缘注入验证服务端接受但回执丢失与无法验证两种情形。
- [ ] 覆盖 Save/Restore 关键阶段取消、超时、关闭会话、操作重入及回退失败；等待操作结束后验证没有迟到的写入和推送。
- [ ] 运行包级检查与测试，实际 Pi 命令冒烟触发可取消操作，形成能够定位状态和恢复方式的记录。
