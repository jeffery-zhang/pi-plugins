# 04: 固定并重建 npm 与 Git 扩展

**What to build:** 用户 Save 时记录当前真正使用的扩展版本和资源筛选；另一台机器 Restore 时重新安装对应 npm 版本与 Git commit，准备失败不会把旧环境切成半套配置。

**Blocked by:** 03: 备份并强制还原原生配置。

**Review:** approved-and-published (historical draft)

- [ ] Save 采集实际安装的 npm 直接版本和 Git commit，保留可重建来源及资源筛选，不把未固定的声明等同于当前实际版本。
- [ ] 来源不能确定、实际版本不可解析或已安装 Git 内容有未包含的本机修改时明确失败，不能静默改用最新版本或丢失修改；提示通过选定本地资源处理的边界。
- [ ] 保留 Pi 包对象中省略、空集合、包含和排除的不同含义，支持相关资源与内置扩展启用状态的原生声明。
- [ ] Restore 在替换受管配置前准备固定来源和依赖，复用 Pi 包管理能力，使用目标机已有的安装命令，不复制依赖树或平台二进制，不误触发 Pi 本体升级。
- [ ] 按实际安装路径验证 Node、npm、pnpm、Bun 或自定义命令的可见性与版本；不将系统 Node 误设为所有运行方式的必需项。
- [ ] 扩展未出现在快照中时从受管加载声明移除；不把安装缓存清理或用户安装目录修改纳入无提示的额外删除。
- [ ] 明确区分版本不存在、私有包或 Git 仓库访问失败、下载超时、安装脚本失败、系统/架构不兼容与外部程序缺失，提示具体包、目标版本及恢复状态。
- [ ] 扩展准备或安装失败时保留或回退原受管文件和声明；可留下载缓存，不承诺安装脚本外部副作用可撤销，不宣称已还原成功。
- [ ] 通过命令入口用本地最小 npm 包 fixture 和 Git 包仓库验证固定版本/commit、筛选与目标机重建，不依赖生产 registry 或用户凭据。
- [ ] 注入解析、下载、安装和平台失败，验证阶段、原因、备份和已有改动提示；真实宿主中重启后能加载预期版本。
- [ ] 运行包级检查与测试，记录包重建和失败恢复证据，并更新使用说明中的直接版本与传递依赖边界。
