# 02: 保存供应商、模型与通用设置快照

**What to build:** 用户执行 Save，将本机供应商、模型与通用偏好保存为远端最新 Environment Snapshot，并保留旧版本；已知敏感位置和本机专属内容不会随原生配置导出。

**Blocked by:** 01: 连接仓库并解释环境与访问问题。

**Review:** approved-and-published (historical draft)

- [ ] 从用户层而非当前项目合并后的有效设置收集原生可移植配置，尊重实际 Agent Directory；不跟随目录外资源或项目，明确提示未覆盖引用。
- [ ] 保存供应商与模型身份、接口与兼容参数、模型元数据覆盖、默认和启用模型以及选定的通用偏好；Shell、代理、编辑器、机器路径与信任状态按本机规则保留。
- [ ] 明确的格式合同包含格式版本、创建时间、创建 Pi 版本、受管类别及内容；未交付类别如包和本地资源不能被宣称已保存完整。
- [ ] 按已知文件与结构化字段规则过滤 Provider/MCP 鉴权位置，不读取独立凭据文件；保留纯环境变量引用，已知字段的字面值和取 Key 命令不导出，不扫描其他任意文本。
- [ ] 不收集会话、安装产物、历史、缓存、自身工作副本、备份或日志；收集或格式验证失败时不发布不完整快照。
- [ ] 在空仓库创建第一个快照，在已有历史上提交本机状态并正常推送；保留原有提交，不强推、不自动合并配置。
- [ ] 提交身份、无写权限、保护分支、提交和推送失败都给出对应阶段、可用退出码与操作建议，准确区分本地快照已生成和远端已更新。
- [ ] 使用临时源环境和真实本地 Git 仓库从命令入口验证首次保存、后续版本、过滤和历史保留；已知凭据不出现在快照或提示中，任意其他文本不会触发审核流程。
- [ ] 验证不可读配置、无效内容、快照必需信息缺失、Git 身份和推送失败；远端竞争可以先明确失败，后续 06 补有界重试和结果未知验证，不伪装成功。
- [ ] 包级检查与测试可运行，实际 Pi 命令冒烟证明远端快照可读取，更新最小使用说明。
