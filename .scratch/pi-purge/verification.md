## 测试分工与边界

- 公开扩展场景与真实 SDK/CLI 契约测试分别保留在 [场景测试](../../packages/pi-purge/test/purge.test.ts) 和 [宿主测试](../../packages/pi-purge/test/host.test.ts)。宿主测试只连接本机临时 HTTP 模拟服务，不消耗模型额度，不读取真实凭据或私有提示正文。
- [本机冒烟](../../packages/pi-purge/test/local-smoke.ts) 使用已配置的本机 DS 服务和提示文件；只输出无私有正文的摘要，会消耗实际模型额度，不包含用户目标场景。
- 工程对照显式使用 max；真实 TUI 的未指定默认档位观察为 high。用户目标场景的完整输入、参数和输出未采集，只保存其通过结论，不推断统计成功率。
- 本机真实 provider 验证范围为 Muryo / DeepSeek V4.1 Flash / OpenAI Responses。其他模型不被白名单排除，但效果未验证；Chat Completions / Anthropic 只做了摘要形状测试，不冒充真实 provider 集成验证。
- 只允许并验证了 Pi 1.4.0；其他宿主版本明确不启用。仓库其他插件的 0.84.3 基线保持不变。
- 确认过默认 system sections 不允许覆盖 preamble，因此实际通过公开 context_with_system 修改请求投影；before_agent_start 只负责本轮准备。不依赖私有 system builder 或英文身份串截断。
- 原生压缩/继续可在同一轮重启 agent，额外的 agent_start 恢复当前正文快照；模型/压缩/树导航清除旧请求观测。后续身份 patch 不重复携带正文，且保留其他工程 patch、工具增删和非 system 历史。
- 已知宿主钩子抛错会被捕获，因此失败策略显式恢复原生路径，不宣称抛错等于阻断请求。
- 用户要求后续包下载走国内镜像；后续如需安装开发依赖，显式使用 `--registry https://registry.npmmirror.com`。当前依赖已齐，之后的测试未下载包。
