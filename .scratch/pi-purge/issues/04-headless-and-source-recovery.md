# 04: 让无 UI 和中途失败保持可观察的原生恢复

**What to build:** 在已通过 DS 行为门槛的版本上，让用户在无 UI 运行、来源先成功后失效、未知请求形状或修复来源后，仍能清楚知道本轮是否生效，并得到完整的正常 Pi 回退，而不会泄露私有内容或破坏宿主输出协议。

**Blocked by:** 02 — 让必验 DS 通过真实目标场景。

**Status:** resolved

- [x] 在 TUI、可用 RPC UI 和无 UI 的 print/JSON 等宿主模式下，插件运行不等待交互、不调用不可用 UI；必要诊断可见，原生结构化输出仍可消费。
- [x] 来源先成功后被移除、变为空白、不可读或无法适配时，下一轮明确报告未生效，并恢复该轮正常 Pi 提示；不静默复用旧成功正文，不保留部分注入。
- [x] 失败状态不会沿用旧的来源、组装或请求成功记录冒充本轮结果；启用意图与本轮实际结果分别展示。
- [x] 来源修复后，通过现有启用动作和下一轮正常组装即可恢复；不新增专用 reload 命令、来源配置层或文件监听功能。
- [x] 用户取消继续遵循 Pi 原生取消路径，不因加载失败恢复逻辑而触发重试、续跑或新的请求。
- [x] 未知或不完整的 provider payload 不引发崩溃，不被默认改写；无法核实的角色、参数或摘要明确标记未知。
- [x] 对已识别请求形状的观察结果准确，状态中来源正文与实际指令的摘要含义清楚；不得把其他模型可加载当成效果已验证。
- [x] 使用虚构敏感标记验证默认日志和状态不包含提示正文、用户正文、工具参数/结果、headers 或凭据；允许摘要仅限既定元数据。
- [x] 基于相同公开扩展场景接缝覆盖模式与中途失败组合，包级 `check`、`test` 通过；无需先完成 03 的全部生命周期完善。
- [x] 真实 Pi 至少实际验证无 UI 正常请求、无 UI 来源失败、来源恢复和退出清理，记录模式、诊断与输出协议证据；不安装插件。
- [x] 若改动影响 DS 指令内容，重新交由用户确认既有行为场景；普通工程任务及已约定的失败恢复语义不退化。
