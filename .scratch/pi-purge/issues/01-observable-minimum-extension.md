# 01: 交付可观察的最小注入版本

**What to build:** 用户能临时加载 Pi Purge，在当前 Pi 中使用已有 DSH 外部提示，同时保留工具和工程信息；通过命令控制启停、查看来源与实际请求摘要，并在初始来源失败时明确恢复正常 Pi 提示。这是一条可交给用户进行 DS 行为验证的完整最小路径，不在本票宣称行为已经生效。

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 可以在本机 Pi 1.4.0 中按 package 方式临时加载，符合仓库 ESM 包和显式扩展入口规范，并按后续独立发布要求补齐元数据；不安装插件、不升级全仓 Pi 基线，不引入额外运行时依赖。
- [x] 加载后的新会话默认启用，从自身安装包读取已验收正文，不依赖外部应用文件；初版来源文件保持原样；不内置占位正文，不设置 provider/model 白名单。
- [x] 先完整读取、校验和适配再应用修改；只做 Pi 工具名、变量及宿主差异所需的必要适配，并能区分原来源摘要与适配后的指令摘要。
- [x] 目标提示位于明确的前部并控制身份与对话行为；当前工具 schema、工具说明、AGENTS、skills、cwd 和具体工程约束保留。角色要求与具体工程约束冲突时，工程约束优先。
- [x] `/purge on`、`/purge off`、`/purge status` 可实际触发；无参数查询状态。停用后的下一轮恢复当轮正常 Pi 提示，重复操作不叠加正文。
- [x] 状态可区分启用意图、来源与组装结果、最近一次请求观测；显示来源、长度和 hash，未观测时不以旧记录宣称当前生效。
- [x] 请求观察只读取 payload，显示可识别的 API、provider/model、指令角色、消息顺序、工具名称和推理参数摘要；不记录正文、工具参数/结果或凭据，不伪称已审计网关最终处理。
- [x] 初始文件缺失、不可读、空白或必要适配失败时，明确报告未生效，本轮完整恢复正常 Pi 提示并继续请求；不得因 Pi 捕获钩子异常而留下部分变更或伪成功状态。
- [x] 基础 UI 调用具备正确守卫，查询或失败报告不依赖必需的交互输入；不写入模型对话充当诊断。
- [x] 使用公开事件和命令场景保留最小可运行检查，证明有效注入、工程信息保留、启停、重复运行和初始失败恢复；包级 `check`、`test` 通过。
- [x] 真实 Pi 临时加载冒烟实际触发命令、一次无敏感内容的工具任务及请求观察；记录提示传输和工具链证据，并明确 DS 行为尚待 02 验收。
- [x] 提供足够的最小使用说明，用户可以开始、关闭并定位状态；不需要先开发后续生命周期完善或完整无 UI 验证功能。
