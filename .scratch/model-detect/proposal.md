## 测试边界提案

以**真实 Pi 会话执行 `/detect`，观察用户交互、磁盘结果与下一次加载后的有效模型参数**作为主要测试边界。使用临时 Agent Environment、本地 HTTP 服务返回公开目录样本，以及 Pi 的 UI 接口提供用户选择/确认；不模拟目标选择、元数据转换或配置写入逻辑。

这是仓库 Pi Sync 和 Pi Purge 宿主测试已有的方式。只在目录 HTTP 和用户输入的外部边界提供可控输入，不新增跨插件公共框架，也不为测试额外拆分业务层。

- 验证命令注册、目标范围、来源选择、确认/取消、结果通知、配置变更、备份与失败后的原值保留。
- 在同一命令边界覆盖目录坏响应、无效字段、超时/取消、并发配置变更、配置发布失败、无 UI 与停机取消。
- 命令运行后用 Pi 自己的模型加载逻辑读取配置，断言有效能力与限制；不只检查 JSON 外形。
- 实际模型请求计数必须为零，日志不得含测试凭据标记；所有写入限定在临时目录。
- 最终用 Pi 1.4.0 实际加载扩展并在 TUI 中触发斜杠命令，检查来源输入、差异预览、取消、确认和重启提示。公开远端接口可做一次独立联网冒烟，确定性测试使用本地样本。

## 正式规格草案

### Problem Statement

Pi 用户已经配置了模型连接，但需要人工查找并填写上下文、最大输出、输入模态、思考控制和价格。自定义 provider 或模型标识可能无法与公开目录直接对应；内置目录更新也不会替用户补全自定义模型配置。手工复制参数容易混淆不同服务提供方的限制，或把缺失数据写成错误值。

### Solution

提供 Pi 1.4+ 的 Model Detect 扩展，通过 `/detect <provider>/<model>` 更新一个已有目标模型，通过 `/detect <provider>` 更新该 provider 显式配置的目标模型集合。扩展查询 models.dev，确定唯一目录条目，统一展示本次差异，在用户一次确认后备份并保存，提示重启 Pi 生效。

用户可以输入来源模型名称或 ID，明确选择一个目录条目，并保存来源映射供后续更新复用。能力、限制和价格统一来自同一来源；需要原厂目录价时选择原厂条目。目录无法确定的字段保持原配置，并在结果中解释。

### User Stories

1. 作为 Pi 用户，我希望在 Pi 内执行 `/detect`，以便用扩展完成参数维护。
2. 作为 Pi 用户，我希望指定一个已识别的 provider/model，以便只更新该目标模型。
3. 作为 Pi 用户，我希望仅指定 provider 就更新显式配置的模型，以便批量维护已有配置。
4. 作为 Pi 用户，我希望批量目标不包含整个内置目录，以便操作范围符合我的配置意图。
5. 作为 Pi 用户，我希望未知目标或空目标集合得到明确说明，以便及时纠正命令。
6. 作为 Pi 用户，我希望模型 ID 内的斜杠得到保留，以便正确定位网关提供的模型。
7. 作为 Pi 用户，我希望相同 provider/model 优先精确匹配目录，以便减少重复输入。
8. 作为自定义模型用户，我希望输入 models.dev 上的模型名称或 ID，以便为本地别名指定来源。
9. 作为自定义模型用户，我希望多个同名候选显示 provider 与完整 ID，以便选择唯一目录条目。
10. 作为 Pi 用户，我希望来源映射按本地目标模型保存，以便后续更新复用对应关系。
11. 作为 Pi 用户，我希望预览显示目标和来源，以便核对参数归属。
12. 作为 Pi 用户，我希望更新上下文和最大输出，以便 Pi 使用目录中明确声明的 token 限制。
13. 作为 Pi 用户，我希望更新文字和图片输入能力，以便配置与模型声明一致。
14. 作为 Pi 用户，我希望目录的其他模态被明确报告，以便知道哪些能力未写入 Pi。
15. 作为 Pi 用户，我希望明确的思考档位转换为 Pi 支持的档位，以便只使用可确定的选项。
16. 作为 Pi 用户，我希望无法准确转换的思考控制保留原配置，以便不把预算或开关误认为固定深度。
17. 作为 Pi 用户，我希望输入、输出及缓存价格可更新，以便 Pi 按来源标价估算成本。
18. 作为代理模型用户，我希望选择原厂目录条目作为统一来源，以便按原厂目录价配置估算参数。
19. 作为 Pi 用户，我希望价格单位和阶梯准确对应 Pi，以便避免数量级与阈值错误。
20. 作为 Pi 用户，我希望缺失价格保持未知或原值，以便不把缺失数据误认为免费。
21. 作为 Pi 用户，我希望无法完整转换的阶梯价格整组保留，以便不混用新基础价和错误阶梯。
22. 作为 Pi 用户，我希望有效目录值更新已有元数据，以便修正过时参数。
23. 作为 Pi 用户，我希望无效或缺失数据得到跳过说明，以便理解哪些配置没有更新。
24. 作为 Pi 用户，我希望部分目标查不到时仍可更新其他目标，以便不必拆开重试整次操作。
25. 作为 Pi 用户，我希望写入前看到整个操作的差异并统一确认，以便控制实际修改。
26. 作为 Pi 用户，我希望取消或超时不会改动配置，以便安全退出操作。
27. 作为 Pi 用户，我希望更新前保留可用备份，以便需要时还原原配置。
28. 作为 Pi 用户，我希望连接、鉴权、请求标识和无关配置保持原样，以便元数据更新不破坏模型连接。
29. 作为 Pi 用户，我希望原有注释和编码得到保留，以便配置可继续维护。
30. 作为 Pi 用户，我希望并发改动或写入失败时保留原文件，以便其他修改与有效配置不丢失。
31. 作为 Pi 用户，我希望结果分别报告更新、未变化和跳过的目标，以便判断操作是否完成。
32. 作为 Pi 用户，我希望完成后明确提示重启生效，以便知道当前会话仍使用原参数。
33. 作为 Pi 用户，我希望此命令不调用模型、不在日志暴露凭据，以便参数维护不会产生模型费用或泄露连接信息。
34. 作为 Pi 用户，我希望没有交互确认能力时命令给出明确结果并保持配置，以便自动化客户端不会绕过确认。

### Implementation Decisions

- 新增独立的 Model Detect 插件包，采用仓库标准 ESM 扩展结构与 `registerCommand`；只提供斜杠命令，最低目标版本为 Pi 1.4，开发与宿主验证先固定 1.4.0。
- 单模型目标可来自 Pi 已识别模型；provider 批量目标取显式模型条目与指向已有模型的覆盖条目的去重并集。未知目标不创建模型，仅有认证而未列目标的 provider 返回空集合说明。
- 命令按首个斜杠划分 provider 与完整模型 ID。参数缺失时展示用法，不扩展全新向导入口。
- 一次操作只请求一次公开 v1 目录，并向请求传递超时与取消信号。目录数据是外部输入，逐项校验所需结构、已知枚举、有限数值及正整数限制。
- 对目标优先使用已保存的来源映射，其次尝试 provider/model 精确命中。需人工对应时允许输入来源名称或 ID，并在存在多个候选时选择唯一目录条目；不自动用模糊匹配结果写入。
- 来源映射以本地目标 provider/model 为键保存在插件自身配置中，随用户确认的更新保存，预览中明确展示。失效映射需重新明确来源，不自动迁移到相似模型。
- 能力、限制与价格统一来自同一选定目录条目；按定价 ADR，原厂目录价通过选定原厂条目获得。无需修改目标请求模型 ID，也不独立推断第二个价格来源。
- 元数据写入 Pi 的模型覆盖层，使原有完整模型定义、连接、鉴权、名称、兼容参数、采样设置及无关覆盖保持不变。
- 上下文与输出分别映射；独立输入限制不冒充上下文。输入模态仅映射 Pi 支持的文字/图片，映射结果为空则保留，其他模态报告未写入。
- 有明确且能准确对应的 effort 时生成完整 Pi 档位映射，不支持项明确禁用，正确区分省略与 null。仅有预算、开关或未知 effort 时保留本地思考组；明确不支持 reasoning 的条目按其确定语义处理。
- 普通价格按 USD/百万 tokens 映射已知项，缺失不填零；目录阶梯须能准确转换且满足 Pi 所需字段。无法保证阶梯与基础价一致时保留整个价格组，避免发布混合价格。
- 可确认值覆盖旧元数据，缺失/无效值保留。有效目标和字段允许部分更新；结果明确统计跳过原因，不能把部分完成报告为全部成功。
- 在一次操作完成查找、验证和差异计算后展示统一预览，只确认一次；未确认不发布模型配置或来源映射。
- 配置写入保留 BOM、UTF-8、换行与注释所需语义，先备份再在同目录准备临时文件，发布前检测并发改动。文件发布失败时保留有效原配置；映射保存与模型保存不得产生未报告的不一致。
- 仅在支持交互的 UI 中执行确认；无 UI 时明确失败且不写入。操作取消、重复调用和 session shutdown 均有明确结束路径；不留下后台请求、进程或 watcher。
- 完成后提示重启生效，不尝试重绑当前模型、不自动调整当前思考级别、不自动重启或退出 Pi。

### Testing Decisions

- 主要断言针对真实斜杠命令可见行为、持久化结果和 Pi 下次加载后的有效模型参数，不针对内部函数名、调用次数或模块拆分。
- 复用 Pi Sync 的真实会话命令测试方式，以及 Pi Purge 的本地 HTTP 和隔离宿主方式；不抽取跨插件通用测试框架。
- 通过本地 HTTP 响应覆盖精确匹配、多候选、模型 ID 含斜杠、缺值、零值、reasoning 各种形态、普通价格、完整/不完整阶梯及网络错误。
- 通过临时 Agent Environment 与 UI 应答覆盖差异展示、一次确认、取消、映射复用、批量部分成功、并发配置更改及发布失败。
- 以 Pi 实际加载器验证覆盖层最终效果，并确认模型数、连接、请求标识、无关配置、注释及原始备份符合约定。
- 将模型请求计数和凭据标记作为外部保护断言；不访问用户配置、不发送真实模型请求。
- 每条任务自带可运行检查，并在最终真实 TUI 冒烟中触发新增交互；联网目录冒烟不充当确定性测试门槛。
- 兼容目标为 1.4+，验证报告列明实际宿主版本；不把只测过 1.4.0 写成未来版本已通过。

### Out of Scope

- 独立 CLI、启动 flag、顶层 `pi detect` 包装、模型工具入口。
- 导入目录中的新模型、自动升级模型 ID、修改连接和鉴权。
- 用模型供应商请求探测实际容量、模态、思考行为或真实账单。
- 实验 v2、完整音视频/PDF 能力及非文本 token 定价。
- 凭模型名推断供应商、为价格另查来源、近似映射未知思考档位。
- 当前会话热更新、自动退出或重启、自动更新及定时同步。
- Pi 1.4 以前版本、全仓重构、共享插件框架、发布或安装插件。

## 任务拆分提案

### 01：单模型基础元数据更新

**Blocked by:** None (can start immediately).

**What it delivers:** 对精确匹配的已有目标执行 `/detect`，拉取目录，上下文/输出/文字图片能力经差异预览后备份保存，并提示重启。

- [ ] 扩展可由 Pi 1.4.0 实际加载；单模型目标存在性及完整 ID 校验正确。
- [ ] 一次操作请求一次目录；基础字段有效值覆盖，缺失/无效值保留并报告。
- [ ] 统一预览、一次确认、取消不写入、原配置备份与覆盖层更新形成完整流程。
- [ ] 用户连接、鉴权、无关配置、注释和编码保持；网络、无 UI、并发改动和配置发布失败不损坏原配置。
- [ ] 真实会话命令边界检查与 TUI 冒烟可运行，断言不触发模型请求，并能由 Pi 下次加载得到新值。

### 02：手工来源映射与复用

**Blocked by:** 01：单模型基础元数据更新。

**What it delivers:** 本地别名模型可输入目录名称/ID并选定唯一来源，确认更新后保存对应关系，下次调用直接复用且继续展示来源。

- [ ] 本地自定义 provider/model 保持身份；目录匹配可接受名称或 ID，多候选不自动选中写入。
- [ ] 已保存映射优先于默认精确匹配，并按目标隔离；失效来源给出重新输入机会或明确跳过。
- [ ] 模型更新和映射保存共享统一预览与一次确认；取消不保存，发布失败不留下未报告的不一致。
- [ ] 覆盖首次映射、重用、歧义、失效、取消、失败及两个目标互不影响的命令级测试。

### 03：思考控制与目录价格更新

**Blocked by:** 01：单模型基础元数据更新。

**What it delivers:** 对已确定来源的单模型，将可准确转换的思考控制和价格纳入同一次预览与更新；无法转换的整组保留并说明。

- [ ] 完整 effort 映射正确禁用不支持档位，明确 reasoning=false 可表达；预算/开关/未知值按已定分组规则保留。
- [ ] 普通 token 与缓存价格单位正确、零价与未知严格区分、缺项保留。
- [ ] 完整阶梯正确转换；无法准确转换或无法保持基础价/阶梯一致时保留整个价格组。
- [ ] 同一次更新的能力和价格来自同一目录条目；选原厂条目即按原厂价配置，不另查价格来源。
- [ ] 命令级测试覆盖明确档位、不可表达控制、缺价、零价、完整/不完整阶梯，Pi 有效模型加载结果符合预览。

### 04：provider 批量更新与最终宿主验证

**Blocked by:** 02：手工来源映射与复用；03：思考控制与目录价格更新。

**What it delivers:** `/detect <provider>` 更新显式配置目标，逐项复用映射或明确来源，统一预览确认、保存，并汇总更新/未变化/跳过结果。

- [ ] 目标集合是显式模型和指向已有模型的覆盖条目的去重并集；内置目录、新模型与其他 provider 不被导入或修改。
- [ ] 仅有认证而未显式列模型时报告没有目标；未知覆盖不被变成新模型。
- [ ] 一次批量操作只取一次目录；混合精确匹配、已保存映射、未命中与字段不可转换均能明确处理。
- [ ] 所有成功项统一预览并只确认一次；取消不写入，网络或文件失败不发布半份模型配置。
- [ ] 逐项与汇总结果准确，备份包含完整原配置，重启提示明确，重复执行无变化可正确报告。
- [ ] 在隔离 Pi 1.4.0 宿主实际执行单项和批量 TUI 流程，验证取消、无 UI、错误及关闭时资源释放，记录实际通过版本。
