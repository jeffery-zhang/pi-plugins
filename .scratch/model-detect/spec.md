# Model Detect

Status: resolved

## Problem Statement

Pi 用户已经配置了模型连接，但需要人工查找并填写上下文、最大输出、输入模态、思考控制和价格。自定义 provider 或模型标识可能无法与公开目录直接对应；内置目录更新也不会替用户补全自定义模型配置。手工复制参数容易混淆不同服务提供方的限制，或把缺失数据写成错误值。

## Solution

提供 Pi 1.4+ 的 Model Detect 扩展，通过 `/detect <provider>/<model> [来源名称或 ID]` 更新一个已有目标模型，通过 `/detect <provider>` 更新该 provider 显式配置的目标模型集合。扩展查询 models.dev，确定唯一目录条目，统一展示本次差异，在用户一次确认后备份并保存，提示重启 Pi 生效。

用户可以输入来源模型名称或 ID，明确选择一个目录条目，并保存来源映射供后续更新复用。能力、限制和价格统一来自同一来源；需要原厂目录价时选择原厂条目。目录无法确定的字段保持原配置，并在结果中解释。

## User Stories

1. 作为 Pi 用户，我希望在 Pi 内执行 `/detect`，以便用扩展完成参数维护。
2. 作为 Pi 用户，我希望指定一个已识别的 provider/model，以便只更新该目标模型。
3. 作为 Pi 用户，我希望仅指定 provider 就更新显式配置的模型，以便批量维护已有配置。
4. 作为 Pi 用户，我希望批量目标不包含整个内置目录，以便操作范围符合我的配置意图。

22. 作为 Pi 用户，我希望有效目录值更新已有元数据，以便修正过时参数。

33. 作为 Pi 用户，我希望此命令不调用模型、不在日志暴露凭据，以便参数维护不会产生模型费用或泄露连接信息。
34. 作为 Pi 用户，我希望没有交互确认能力时命令给出明确结果并保持配置，以便自动化客户端不会绕过确认。

## Implementation Decisions

- 新增独立的 Model Detect 插件包，采用仓库标准 ESM 扩展结构与 `registerCommand`；只提供斜杠命令，最低目标版本为 Pi 1.4，开发与宿主验证先固定 1.4.0。
- 单模型目标可来自 Pi 已识别模型；provider 批量目标取显式模型条目与指向已有模型的覆盖条目的去重并集。未知目标不创建模型，仅有认证而未列目标的 provider 返回空集合说明。
- 命令按首个斜杠划分 provider 与完整模型 ID。单模型目标后可附来源名称或 ID，名称可包含空格，用于显式指定或替换映射；批量模式按目标逐一映射。参数缺失时展示用法，不扩展全新向导入口。
- 一次操作只请求一次公开 v1 目录，并向请求传递超时与取消信号。目录数据是外部输入，逐项校验所需结构、已知枚举、有限数值及正整数限制。
- 对目标优先使用已保存的来源映射，其次尝试 provider/model 精确命中。需人工对应时允许输入来源名称或 ID，并在存在多个候选时选择唯一目录条目；不自动用模糊匹配结果写入。
- 来源映射以本地目标 provider/model 为键保存在插件自身配置中，随用户确认的更新保存，预览中明确展示。失效映射需重新明确来源，不自动迁移到相似模型。
- 能力、限制与价格统一来自同一选定目录条目；按定价 ADR，原厂目录价通过选定原厂条目获得。无需修改目标请求模型 ID，也不独立推断第二个价格来源。
- 元数据写入 Pi 的模型覆盖层，使原有完整模型定义、连接、鉴权、名称、兼容参数、采样设置及无关覆盖保持不变。
- 上下文与输出分别映射；独立输入限制不冒充上下文。输入模态仅映射 Pi 支持的文字/图片，映射结果为空则保留，其他模态报告未写入。
- 有明确且能准确对应的 effort 时生成完整 Pi 档位映射，不支持项明确禁用，正确区分省略与 null。仅有预算、开关或未知 effort 时保留本地思考组；明确不支持 reasoning 的条目按其确定语义处理。
- 普通价格按 USD/百万 tokens 映射已知项，缺失不填零；目录阶梯须能准确转换且满足 Pi 所需字段。无法保证阶梯与基础价一致时保留整个价格组，避免发布混合价格。
- 可确认值覆盖旧元数据，缺失/无效值保留。有效目标和字段允许部分更新；结果明确统计跳过原因，不能把部分完成报告为全部成功。
- 在一次操作完成查找、验证和差异计算后展示统一预览，只确认一次；未确认不发布模型配置或来源映射。
- 配置写入保留 BOM、UTF-8、换行与注释所需语义，先备份再在同目录准备临时文件，发布前检测并发改动。文件发布失败时保留有效原配置；映射保存与模型保存不得产生未报告的不一致。
- 仅在支持交互的 UI 中执行确认；无 UI 时明确失败且不写入。操作取消、重复调用和 session shutdown 均有明确结束路径；不留下后台请求、进程或 watcher。
- 完成后提示重启生效，不尝试重绑当前模型、不自动调整当前思考级别、不自动重启或退出 Pi。

## Testing Decisions

- 主要断言针对真实斜杠命令可见行为、持久化结果和 Pi 下次加载后的有效模型参数，不针对内部函数名、调用次数或模块拆分。
- 复用 Pi Sync 的真实会话命令测试方式，以及 Pi Purge 的本地 HTTP 和隔离宿主方式；不抽取跨插件通用测试框架。
- 通过本地 HTTP 响应覆盖精确匹配、多候选、模型 ID 含斜杠、缺值、零值、reasoning 各种形态、普通价格、完整/不完整阶梯及网络错误。
- 通过临时 Agent Environment 与 UI 应答覆盖差异展示、一次确认、取消、映射复用、批量部分成功、并发配置更改及发布失败。
- 以 Pi 实际加载器验证覆盖层最终效果，并确认模型数、连接、请求标识、无关配置、注释及原始备份符合约定。
- 将模型请求计数和凭据标记作为外部保护断言；不访问用户配置、不发送真实模型请求。
- 每条任务自带可运行检查，并在最终真实 TUI 冒烟中触发新增交互；联网目录冒烟不充当确定性测试门槛。
- 兼容目标为 1.4+，验证报告列明实际宿主版本；不把只测过 1.4.0 写成未来版本已通过。

## Out of Scope

- 独立 CLI、启动 flag、顶层 `pi detect` 包装、模型工具入口。
- 导入目录中的新模型、自动升级模型 ID、修改连接和鉴权。
- 用模型供应商请求探测实际容量、模态、思考行为或真实账单。
- 实验 v2、完整音视频/PDF 能力及非文本 token 定价。
- 凭模型名推断供应商、为价格另查来源、近似映射未知思考档位。
- 当前会话热更新、自动退出或重启、自动更新及定时同步。
- Pi 1.4 以前版本、全仓重构、共享插件框架、发布或安装插件。

## 会话生效的已核实事实

Pi 1.4.0 的 registry.refresh 不会回写当前 session.model；其当前值是 agent.state.model。公开 pi.setModel 可以重选相同模型，但会追加会话记录、重新计算并钳制 thinkingLevel；scopedModels 仍可能持有旧 Model。两者都不自动检查 idle。详细来源见研究文档“当前会话元数据刷新边界”。首版已决定提示重启生效；以上事实记录保留为后续热更新设计的依据。

## 最终理解摘要

1. Pi 1.4+ 扩展仅提供 `/detect` 斜杠命令；单模型可指定 Pi 已识别目标，provider 批量目标只包含显式配置的已有模型，不导入模型。
2. 精确匹配优先；允许输入 models.dev 名称或 ID，同名候选需选定唯一 provider/model。来源映射按本地目标持久化，后续单项/批量复用，预览显示来源。
